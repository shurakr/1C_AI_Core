
# 1C_AI_Core

**Интеллектуальная подсистема семантического анализа, нормализации данных и MDM-автоматизации для экосистемы 1С.**

---

## 📌 Описание проекта

**1C_AI_Core** -- это высокопроизводительный «умный мост» между реляционными данными платформы 1С:Предприятие 8 (ERP, УПП, БП) и современными технологиями векторного поиска и больших языковых моделей (LLM).

Система позволяет не просто искать совпадения строк, а анализировать **семантический смысл** хозяйственных операций. Это дает возможность сопоставлять объекты (документы, элементы справочников) даже в тех случаях, когда их текстовое описание или артикулы значительно различаются, но бизнес-суть идентична.

---

## 🚀 Сценарии использования (Use Cases)

### 1\. Интеллектуальный импорт первичных данных

При загрузке «сырых» данных из внешних источников (банк, чеки, Excel-прайсы) система анализирует контекст и находит наиболее подходящий эталонный объект в текущей базе 1С:

-  Автоматический подбор **Договора** по назначению платежа.

-  Сопоставление **Статей затрат** и **Номенклатуры**.

-  **Результат:** Сокращение времени на ручную обработку данных в 5-10 раз.

### 2\. Подготовка данных для MDM (Мастер-данные)

Эффективный инструмент для очистки и синхронизации справочников при миграции данных или объединении разрозненных информационных баз (например, переход с 1С:УПП на 1С:ERP):

-  Семантическая «склейка» дублей.

-  Сопоставление объектов с несовпадающими уникальными идентификаторами (UUID).

-  **Результат:** Чистая и структурированная нормативно-справочная информация.

### 3\. Автозаполнение аналитик в документах

Интеллектуальный помощник при вводе документов. Система находит в истории похожие операции и предлагает наиболее вероятные значения для заполнения реквизитов аналитического учета.

-  **Результат:** Минимизация ошибок «человеческого фактора» и повышение качества учета.

### 4\. Работа с историческими базами при смене конфигурации

При переходе на новую учетную систему (например, с 1С:УПП на 1С:ERP) огромный массив накопленных документов и справочников часто остается во внешней «старой» базе, которую нецелесообразно полностью переносить.

-  Данные исторической базы выгружаются через COM-соединение и индексируются в Qdrant. При анализе нового объекта Python-сервис ищет подходящий аналог в этом индексе.
-  Сервис возвращает ссылку на выбранный объект и объясняет совпадения и различия. Получение полного документа и правила переноса его реквизитов в текущий документ реализуются на стороне 1С.
-  **Результат:** Использование исторических документов как примеров для заполнения новых, без полного переноса истории в текущую базу.

## 🧠 Ключевые механизмы (Engine Logic)

### Smart Normalizer (Умная очистка и обогащение)

Критически важный компонент, который готовит «цифровой отпечаток» объекта перед векторизацией. Модуль выполняет:

1. **Техническую гигиену:** Удаление шума (спецсимволы, лишние пробелы, технические переносы).

2. **Бизнес-экстракция:** Извлечение из объекта ключевых бизнес-признаков (ИНН, Суммы, Ключевые слова, Иерархия папок). Это позволяет векторной модели фокусироваться на идентификационных признаках, а не на случайном текстовом шуме.

### Многоуровневый поиск (Search Levels)

Для обеспечения баланса между скоростью и точностью используется каскадная логика:

-  **L1: Fast-Track (Мгновенный путь):** Сравнение векторов, названий и строгих реквизитов. Условия быстрого выбора: векторное сходство > 0.92, сходство названий ≥ 0.90 и совпадение общих строгих ключей. При отсутствии общих ключей требуется сходство наборов слов ≥ 0.80. Хеш используется отдельно — чтобы пропускать неизменившиеся объекты при загрузке истории.

-  **L2: RAG Pipeline (Интеллектуальный выбор):** В коде предусмотрена передача кандидатов в LLM через совместимый API для экспертной оценки контекста. В текущей реализации при непустой выдаче запасная ветка Fast-Track возвращает лучшего кандидата, даже если пороги не пройдены, поэтому до LLM анализ не доходит. Значение `confidence=99` в этом пути задано фиксированно и не является рассчитанной вероятностью.

### Гибридная интеграция с 1С

-  **AI_Core Extension:** Нативная интеграция через HTTP-сервисы для современных конфигураций.

-  **COM-Proxy механизм:** Уникальная возможность внедрения ИИ-функций в устаревшие системы (**1С:УПП 1.3**) без внесения изменений в их конфигурацию.

## 📂 Структура проекта

### 🐍 Python Backend (FastAPI)

* **`app/main.py`** — Диспетчер внешних запросов. Описывает HTTP-интерфейс (FastAPI), управляет жизненным циклом приложения (lifespan) и маршрутизирует входящие данные от 1С к внутренним сервисам.
* **`app/rag_pipeline.py`** — Интеллектуальный «арбитр» системы. Реализует гибридный поиск: от мгновенного сопоставления (Fast-Track) до сложной RAG-цепочки с использованием LLM в качестве эксперта для принятия финального решения.
* **`app/normalizer.py`** — Слой канонизации и очистки. Выполняет «бизнес-гигиену» данных: удаляет шум, нормализует строки (Regex/Словари) и формирует компактные слепки объектов для максимально точного векторного поиска.
* **`app/object_comparison.py`** — Сравнение ключевых реквизитов исходного объекта и выбранного аналога: совпадения, различия и недостающие данные. Имена полей обрабатываются независимо от регистра.
* **`app/qdrant_store.py`** — Слой работы с персистентными данными. Инкапсулирует логику взаимодействия с Qdrant: создание коллекций, управление полезной нагрузкой (payload) и низкоуровневые поисковые запросы.
* **`app/indexer.py`**- Координатор пакетной загрузки. Организует массовую передачу данных из 1С в векторное пространство, обеспечивая целостность и атомарность обновления истории объектов.
* **`app/models.py`** — Декларативное описание протоколов обмена. Использует Pydantic для валидации и строгой типизации данных, обеспечивая единый «язык общения» между BSL (1С) и Python.
* **`app/config.py`** — Центр управления параметрами. Хранит глобальные константы: настройки нейросетевых моделей, параметры доступа к внешним API и тд.

### 📦 1C Side (Объекты расширения AI_Core)

#### **Ключевые объекты**

-  **Общие модули**:

   -  `**AI_Core\_Сценарии**`: Ядро бизнес-логики. Управляет вызовами анализа и алгоритмами автоматического заполнения реквизитов.

   -  `**AI_Core\_Сериализация**`: Движок трансформации. Рекурсивно преобразует объекты 1С в JSON для передачи в нейросеть.

   -  `**AI_Core\_ОбменСервисом**`: Транспортный уровень. HTTP-взаимодействие, работа с таймаутами и адресацией.

   -  `**AI_Core\_ИнтеграцияУПП**`: COM-шлюз. Обеспечивает подключение к внешним базам (УПП 1.3 и тп.) для выгрузки и анализа документов и справочников.

-  `**AI_Core\_ВнешниеИнформационныеБазы**` (Справочник): Реестр настроек соединений для интеграции с другими 1С конфигурациями через COM-мост.

-  `**AI_Core\_РезультатыАнализаОбъектов**` (Регистр сведений): База знаний системы. Хранит историю запросов, UUID найденных эталонов и Confidence Score.

-  `**AI_Core\_Проверка**` (Обработка): Форма для ручного тестирования API, качества сериализации и точности поиска.

#### **Вспомогательные объекты**

-  `**AI_Core\_АдресСервиса**` (Параметр сеанса): Хранит актуальный URL Python-сервера для текущего сеанса.

-  `**AI_Core\_ОсновнаяРоль**` (Роль): Права доступа к функционалу интеллектуального анализа.

-  `**AI_Core\_СценарииКлиент**` (Общий модуль): Клиентский обработчик команд БСП. Отвечает за извлечение ссылок из текущего контекста и открытие формы анализа.

-  **Общие формы**:

   -  `**AI_Core\_УниверсальныйВыборИзСписка**`: Форма для выбора объекта метаданных для выгрузки/анализа.

   -  `**AI_Core\_ФормаВыбораИзВнешнейБазы**`: Форма для поиска и выбора объектов в сторонних базах через COM-мост.

-  `**AI_Core\_СтатусыАнализаОбъекта**` (Перечисление): Типизация состояний обработки (бизнес-результаты анализа).

## 🛠 Технологический стек

-  **Backend:** Python 3.14+, FastAPI.

-  **Vector Engine:** Qdrant.

-  **AI Models:**

   -  `FastEmbed` -- быстрая локальная векторизация.

   -  `OpenAI-совместимый API` -- доступ к LLM через RouterAI или OpenRouter; провайдер и модель задаются в `.env`.

-  **1C Side:** BSL (Расширение `AI_Core`), COM Connector, HTTP-интерфейсы.

## ▶️ Запуск Python-сервиса

Команды для PowerShell из каталога проекта. Рабочее окружение проекта — Python 3.14.

При первой установке:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Скопируйте шаблон настроек и укажите свой API-ключ:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Если `.env` уже существует, сохраните свои настройки. Пример настроек для RouterAI:

```dotenv
# BASE_URL="https://openrouter.ai/api/v1"
BASE_URL="https://routerai.ru/api/v1"
OPENROUTER_API_KEY="ваш_ключ_выбранного_провайдера"
OPENROUTER_MODEL="google/gemini-2.5-flash"
```

Имя `OPENROUTER_API_KEY` сохраняется и для RouterAI. Укажите модель, доступную у выбранного провайдера. Для переключения на OpenRouter закомментируйте адрес RouterAI, раскомментируйте адрес OpenRouter и замените ключ.

Обычный запуск:

```powershell
.\.venv\Scripts\python.exe main.py
```

Корневой `main.py` сам запускает Uvicorn на `0.0.0.0:8000` с автоматической перезагрузкой Python-кода. В этом файле адрес и порт заданы явно; параметры `HOST` и `PORT` из `.env` их не переопределяют. После изменения `.env` перезапустите сервис.

- Проверка состояния: [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health).
- Описание API: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).
- Для подключения 1С с другого компьютера используйте `http://<IP_сервера>:8000`.
- Остановка сервиса — `Ctrl+C`.

Qdrant работает локально в `storage/qdrant`, отдельный сервер Qdrant для текущей конфигурации не требуется. При первом использовании модели векторизации может потребоваться её загрузка в `.models_cache`.
